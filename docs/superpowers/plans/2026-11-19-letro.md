# LETRO Implementation Plan

> **For agentic workers:** execute task-by-task. Each task ends with a green
> check and a commit. The tasks are tightly coupled (one Python package), so
> native sequential execution is chosen; a fresh reviewer checks the whole
> branch at the end.

**Goal:** Ship a reproducible, isolated RL environment for a financial-audit
agent that passes the Genesis FinTech hidden checks and demonstrably earns
90+/100 on the published rubric.

**Architecture:** A deterministic generator builds a clean double-entry
company, injects four error classes plus composites, and emits open files,
closed truth and provenance. `AuditEnv` exposes read-only tools over open data
only; truth lives in an evaluator owned by the runner. A single matcher and
reward implementation is shared by training, evaluation and verification.

**Tech Stack:** Python 3.11, standard library only, `unittest`, CSV/JSON/JSONL,
Docker `python:3.11-slim`.

**Spec:** `docs/superpowers/specs/2026-11-19-letro-design.md`

## Global Constraints

- Python 3.11 compatible; no third-party runtime or test dependencies.
- Offline: no network, no GPU, no paid APIs.
- Values: ISO-8601 timestamps with offset, integer minor units, FX rates as
  decimal strings, explicit `null` for absent links.
- Limits: 200–2000 ledger rows, 20–200 documents, 0–12 issues, 100 steps,
  50 rows per page, 30 findings, 10 evidence IDs, 1000 explanation chars.
- Reward: `clip(2*F1 - 1 - 0.002*inspection_steps, -1, 1)`; no shaping.
- Closed truth never appears in observations, trajectories, errors or paths.
- One command: `python -m letro.verify`; exit non-zero on any failure.
- All money math in integer minor units or `Decimal`; never binary floats.
- Fictional companies only; no real financial or personal data.

## Review Focus

- A policy submits IDs it guessed; the matcher must not award TP without a
  complete allowed evidence set and exact canonical affected IDs.
- A clean episode with an empty submission must score F1=1 and reward 1.0;
  a clean episode with any finding must score 0.
- Duplicate findings and resubmission after `terminated` must not add reward.
- Malformed actions and malformed findings must consume a step or terminate
  with -1, never crash or leak a traceback with truth.
- Permuting row order and renaming IDs must preserve oracle F1=1 and reward.

## Task 1: Skeleton, schema, money, RNG, and generator core

**Files:** `letro/__init__.py`, `letro/constants.py`, `letro/schema.py`,
`letro/money.py`, `letro/rng.py`, `letro/generator/company.py`,
`letro/generator/errors.py`, `letro/generator/episode.py`,
`tests/test_schema.py`, `tests/test_money.py`, `tests/test_generator_core.py`,
`pyproject.toml`, `.gitignore`, `LICENSE`.

**Interfaces:**
- `derive_seed(seed: int, stream: str) -> int`
- `to_minor(value: str, currency: str) -> int`, `convert(amount_minor, rate) -> int`
- `Episode` dataclass: `manifest`, `ledger`, `invoices`, `payments`, `fx`,
  `policy`, `truth`, `provenance`.
- `generate_episode(seed, config) -> Episode`
- `render_open_files(episode, directory) -> None`
- `write_closed_files(episode, directory) -> None`

**Acceptance:** clean books balance per currency; invoice totals equal line
items; two error types (`duplicate_invoice`, `payment_allocation_gap`) produce a
measurable delta; same seed gives byte-identical output; invalid config raises
`ConfigError`.

## Task 2: Full error taxonomy, clean cases, composites, reference audit

**Files:** `letro/generator/errors.py`, `letro/generator/episode.py`,
`letro/generator/audit.py`, `tests/test_errors.py`, `tests/test_invariants.py`.

**Interfaces:**
- `inject(episode, rng, counts) -> list[TruthIssue]`
- `reference_audit(open_data) -> list[Finding]` (uses open files only)
- `assert_invariants(episode) -> None`

**Acceptance:** all four types and two composites; clean episodes with split
payments, refunds and recurring amounts; every truth issue has a measurable
expected amount, canonical IDs and ≥1 allowed evidence set; `reference_audit`
reproduces the oracle findings from open files; no contradictory data.

## Task 3: Environment, tools, matcher, reward, evaluator

**Files:** `letro/env.py`, `letro/tools.py`, `letro/matcher.py`,
`letro/reward.py`, `letro/evaluator.py`, `tests/test_env_contract.py`,
`tests/test_matcher.py`, `tests/test_reward.py`, `tests/test_leaks.py`.

**Interfaces:**
- `AuditEnv(open_data, finalize=None)`; `reset(seed=None, config=None,
  episode=None) -> (observation, info)`; `step(action) -> (observation, reward,
  terminated, truncated, info)`.
- `match(truth, findings, tolerance_minor=1) -> MatchResult` with TP/FP/FN,
  P/R/F1, matched pairs and reasons.
- `terminal_reward(f1, inspection_steps) -> float`
- `Evaluator(episode)`; `submit_result(findings) -> dict`; env never holds truth.

**Acceptance:** 100-step cap, 50-row pages with stable cursors, safe calculator
(AST allowlist), bounded errors, malformed submit = -1, eval mode returns 0
reward and no diagnostics, reset isolation, no truth keys in observations,
matcher one-to-one and attacks scored correctly.

## Task 4: Episodes, policies, trajectories, permutation, verifier

**Files:** `scripts/build_episodes.py`, `letro/policies/*.py`,
`letro/trajectory.py`, `letro/permute.py`, `letro/verify.py`,
`episodes/train/*`, `episodes/dev/*`, `trajectories/trajectories.jsonl`,
`tests/test_reproducibility.py`, `tests/test_attacks.py`,
`tests/test_verify.py`.

**Interfaces:**
- `load_episode(directory) -> Episode`
- `permute_episode(episode, salt) -> Episode`
- Policy protocol `act(observation) -> dict`; four adapters.
- `run_episode(env, policy, recorder) -> RunResult`
- `verify_all(root) -> Report`; CLI `python -m letro.verify`.

**Acceptance:** 10 train + 10 dev episodes (5 clean, 5 composite in dev);
random/reconciliation/mark-all/oracle adapters; trajectories JSONL with the
required fields and no truth; permutation preserves oracle F1=1 and reward;
verifier prints the five-criterion table and exits 0.

## Task 5: Packaging, docs, demo, failure analysis

**Files:** `README.md`, `DESIGN.md`, `docs/FAILURE-ANALYSIS.md`,
`Dockerfile`, `.dockerignore`, `scripts/demo.py`, `docs/superpowers/plans/*`.

**Acceptance:** one command from a clean clone; Docker check documented;
design note; measured failure analysis from actual runs; honest limitations;
license and pinned dependencies.

## Task 6: Production-readiness audit and final review

**Files:** `docs/READINESS.md`, `docs/evidence/*`.

**Acceptance:** P1 cold start, P2 trust, P3 claims/UX, P4 release each have
evidence; no critical finding; verdict 90+/100; fresh-context reviewer finds no
blocking issue.
